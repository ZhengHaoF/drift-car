# ADR-0004: 技术栈与视觉方案

日期: 2026-11-07
状态: 已接受

## 背景

目标平台为手机网页。参考广告是 3D 观感（斜俯视、可见车身侧面、光影），需在观感与手机性能/开发成本间取舍。

## 决策

1. **技术栈**：Vite + TypeScript + Three.js（无其他运行时依赖）。
   - 理由：主要迭代是"调漂移手感参数"，热更新 + `npm run dev` 局域网真机调试是刚需；`dist` 产物可部署任意静态托管。
2. **视觉**：真 3D——透视相机斜俯视、固定不旋转、跟随车；复刻广告色块风（橙底灰路 / 黄底绿路）；路面斜向铺设，车沿世界对角方向行驶（屏幕上呈现 45°/135°）。
3. 代码分层：游戏逻辑 / 渲染 / 路面生成解耦，便于以后更换渲染方案。

## 否决方案

- **Canvas 2D / PixiJS**：成本低但广告的"3D 感"需要贴图造假透视，得不偿失（用户明确选 3D）。
- **零构建单文件**：无热更新，调手感迭代慢。

## 后果

- 需控制手机端性能预算（draw call、粒子数量、像素比上限）。
- Three.js 体积较大，需关注首屏加载（代码分割 / 压缩）。
- 车模型来源（程序化拼装 vs 外部 glTF）待定。
